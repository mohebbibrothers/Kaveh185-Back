# استقرار فرانت کاوه ۱۸۵ روی همان هاست cPanel

> **خلاصهٔ یک‌خطی:** فرانت Next به HTML/JS/CSS ایستا تبدیل می‌شود و **از درون خودِ جنگو** سرو می‌شود — بی‌هیچ فرآیند Node، بی‌CORS، با یک مبدأ.

---

## ۱. چرا این معماری (و نه Vercel، و نه `next start`)

| گزینه | چرا رد شد |
|---|---|
| **`next start` پایدار روی هاست** | میزبان فرآیند دائمی ندارد: سقف فرآیند LVE، نبودِ systemd. با هر بازنشانی سرویس کشته می‌شود و سایت بی‌صدا می‌افتد — بی‌هیچ خطای ۵۰۰ که خبر بدهد. |
| **Vercel** | کاربر درخواست کرد روی همین هاست بالا بیاید؛ و با Vercel دو مبدأ می‌شود: CORS، کوکی میان‌مبدأ، و هزینهٔ پهنای‌باند برای هر بازدید. |
| **PHP به‌جای Node** | یک لایهٔ تازه بود که همان کار جنگو را می‌کرد، با یک runtime بیشتر برای نگهداری. |
| **خروجی ایستا، سرو از جنگو** ✅ | همان الگویی که روی این میزبان برای پروژهٔ مهدیه جواب داده. یک مبدأ، بدون Node، بدون کرنل جدا. |

### پیامدها که باید بدانید

- **SSR نداریم.** HTML در زمان ساخت پخته می‌شود؛ شمارش معکوس و جدول‌ها پس از بارگذاری در مرورگر تازه می‌شوند (هر ۶۰ ثانیه، و فقط وقتی برگه دیده می‌شود).
- **بک‌اند باید `kaveh185.ir` را در `DJANGO_ALLOWED_HOSTS` داشته باشد** (نه فقط `api.kaveh185.ir`).
- دادهٔ صفحهٔ اول در HTML هم هست (سئو + نمایش فوری). یعنی **بک‌اند باید هنگام `pnpm build` در دسترس باشد**؛ وگرنه همان عدد و تاریخ سالمِ زمان ساخت می‌آید و بقیه پوستهٔ خالی صادقانه.

---

## ۲. یک‌بار: زیرساخت روی هاست

### ۲.۱ دامنه

سایت روی `kaveh185.ir` است، API روی `api.kaveh185.ir`. هر دو باید **به همان اپلیکیشن Passenger** که بک‌اند روی آن است برسند:

```bash
# فقط‌خواندنی — چه چیزی الان کجاست؟
uapi DomainInfo domains_data | python3 -c "import sys,json;d=json.load(sys.stdin)['result']['data'];print(json.dumps(d['main_domain'],ensure_ascii=False,indent=1))"
uapi DomainInfo list_domains
```

- `kaveh185.ir` باید دامنهٔ **اصلی** حساب (`kavehir`) یا افزونه (addon) روی `public_html` باشد.
- اگر دامنهٔ اصلی حساب چیز دیگری است، `kaveh185.ir` را به‌عنوان addon domain روی همان ریشهٔ سند اضافه کنید — این کار از cPanel → Domains انجام می‌شود و güçهٔ TLS را خودش می‌گیرد.

### ۲.۲ متغیرهای محیطی (آپلود، یک‌بار)

در `~/Kaveh185-Back/.env`:

```env
DJANGO_ALLOWED_HOSTS=kaveh185.ir,www.kaveh185.ir,api.kaveh185.ir

# پوشهٔ فرانت. اسکریپت استقرار همین را می‌سازد و نگه می‌دارد.
FRONTEND_DIST=/home/kavehir/kaveh185-front/current
```

سپس `touch ~/Kaveh185-Back/tmp/restart.txt`. دسترسی `.env` باید `600` بماند.

> **نکتهٔ امنیتی:** `FRONTEND_DIST` تنها تنظیم تازه است. اگر مسیرش غلط باشد، سایت صفحهٔ ۵۰۳ فارسی می‌دهد (نه ۵۰۰ خام) و **API دست‌نخورده کار می‌کند**.

## ۳. ساخت بستهٔ فرانت (روی ماشین خودتان یا CI)

```bash
cd Kaveh185-Front
pnpm install --frozen-lockfile
pnpm build            # → out/  (ایستا، بدون سرور)
pnpm pack:front       # → release/frontend-<sha>.tar.gz (+ .sha256)
```

`pack:front` سه کار می‌کند:

1. **دروازهٔ محتوا:** وجود `index.html`، `404.html`، وجود بارِ RSC (`index.txt`) برای هر صفحه، و اینکه هر `src`/`href` به یک چانک واقعی اشاره کند. اگر نباشد، بسته ساخته نمی‌شود.
2. **فشرده‌سازی از پیش:** همزاد `.br` و `.gz` هر فایل متنی — چون Passenger فشرده نمی‌کند و CPU هاست اشتراکی است. (۱.۲MB ← ۳۲۰KB)
3. **`BUILD_INFO.json`** با هش SHA-256 تک‌تک فایل‌ها + `routes.json`.

نمونهٔ خروجی:

```
✓ بستهٔ فرانت آماده شد
  مسیرها: 9 — / /404/ /login/ /mosques/ /receipt/ /register/ /rules/ …
  فایل‌ها: 66
  متن خام: 1271KB → brotli 321KB (−75٪) · gzip 348KB
  بسته: release/frontend-8370bf3ffa5f.tar.gz (2.1MB)
  sha256: …
```

## ۴. استقرار روی هاست

بسته را آپلود کنید (`~/frontend-xxxx.tar.gz`) و:

```bash
bash ~/Kaveh185-Back/deploy/front-deploy.sh --bundle ~/frontend-xxxx.tar.gz
```

هشت گام، هر کدام یک دروازه:

| # | گام | اگر شکست بخورد |
|---|---|---|
| ۱ | پیش‌نیازها (جنگو، `frontend.py`, ابزارها) | چیزی تغییر نمی‌کند |
| ۲ | راستی‌آزمایی sha256 + بازکردن امن (بدون `..` و مسیر مطلق) | چیزی تغییر نمی‌کند |
| ۳ | دروازهٔ محتوا + بررسی هش تک‌تک فایل‌ها | چیزی تغییر نمی‌کند |
| ۴ | ساخت `releases/<id>` با دسترسی درست | چیزی تغییر نمی‌کند |
| ۵ | پیوند `~/Kaveh185-Back/frontend → current` و `FRONTEND_DIST` در `.env` | چیزی تغییر نمی‌کند |
| ۶ | جابه‌جایی **اتمی** `current` + `touch tmp/restart.txt` | — |
| ۷ | راستی‌آزمایی **از بیرون**: سرآیند `X-Frontend-Build`، ۲۰۰ روی صفحات، ۴۰۴ واقعی، سلامت API | **بازگشت خودکار** به نسخهٔ قبلی |
| ۸ | هرس (نگه‌داشتن ۳ نسخهٔ آخر) | هشدار، سایت سالم است |

### فرمان‌های روزمره

```bash
bash deploy/front-deploy.sh --status     # کدام نسخه سرو می‌شود؟ پاسخ سایت؟ سلامت API؟
bash deploy/front-deploy.sh --rollback   # بازگشت فوری (بی‌بازنشانی کامل)
bash deploy/front-deploy.sh --dry-run --bundle x.tar.gz
```

### چطور مطمئن شوم نسخهٔ درست سرو می‌شود؟

```bash
curl -sI https://kaveh185.ir/ | grep -i x-frontend-build
# X-Frontend-Build: 0.1.0 8370bf3ffa5f
```

همین شناسه در `BUILD_INFO.json` بسته هم هست. اسکریپت استقرار در گام ۷ خودش این تطبیق را انجام می‌دهد و اگر نخواند، برمی‌گردد.

## ۵. آن‌چه سرو می‌شود (قرارداد مسیرها)

| مسیر | چه چیزی | کش |
|---|---|---|
| `/`, `/register/`, `/rules/` … | `out/<route>/index.html` | `no-cache` (همیشه بازبینی) |
| `/<route>/index.txt`, `__next.*.txt` | بارِ RSC برای ناوبری داخلی | `no-cache` |
| `/_next/static/**` | چانک‌های JS/CSS (هش در نام) | **۱ سال، immutable** |
| `/img/**`, `/fonts/**`, `/icon-*.png`, `/og.png` | تصاویر و فونت | ۷ روز |
| `/robots.txt`, `/manifest.webmanifest` | فایل‌های ریشه | ۱ ساعت |
| `/register` (بی‌اسلش) | **۳۰۸** → `/register/` | — |
| `/api/v1/**` | جنگو، دست‌نخورده | طبق بک‌اند |
| مسیر ناشناخته | `out/404.html` با **وضعیت ۴۰۴ واقعی** | `no-store` |

> `/img/` عمداً انتخاب شد و `/media/` نه: `/media/` مال `MEDIA_URL` جنگو است و برخورد، فایل‌های آپلودی را با تصاویر فرانت قاطی می‌کرد.

### امنیت

- **CSP با هش، نه `unsafe-inline`:** هر سند HTML سیاست خودش را با هش SHA-256 اسکریپت‌های درون‌خطی Next می‌گیرد. `default-src 'self'`، `object-src 'none'`، `frame-ancestors 'none'`.
- **پاسخ‌های JSON همان سیاست سخت‌گیرانهٔ قبلی** (`default-src 'none'`) را نگه می‌دارند.
- مسیر پیمایش‌شده (`..`, `%2e%2e`) رد می‌شود و پیوندهای نمادین بیرون از بسته سرو نمی‌شوند.

## ۶. عیب‌یابی

| نشانه | علت و درمان |
|---|---|
| صفحهٔ ۵۰۳ «سایت لحظه‌ای در دسترس نیست» | `FRONTEND_DIST` به پوشه‌ای اشاره می‌کند که `index.html` ندارد. `bash deploy/front-deploy.sh --status` و سپس `--bundle` دوباره. |
| سایت بالا می‌آید ولی **بی‌استایل و بی‌تعامل** | CSP جواب نداده. `curl -sI https://kaveh185.ir/ \| grep -i content-security` — باید `default-src 'self'` و حداقل یک `sha256-` داشته باشد. اگر `default-src 'none'` بود، بک‌اند به‌روز نیست. |
| هر کلیک روی لینک داخلی **کل صفحه را دوباره بارگذاری می‌کند** | فایل‌های `index.txt` (بارِ RSC) سرو نمی‌شوند. وجودشان در بسته را بررسی کنید. |
| `400 Bad Request` | `kaveh185.ir` در `DJANGO_ALLOWED_HOSTS` نیست. |
| صفحات ۲۰۰ ولی محتوای قدیمی | کش مرورگر روی HTML. سرآیند باید `no-cache` باشد؛ `curl -sI` را چک کنید. |
| تایمر عدد عجیب می‌دهد | دادهٔ زمان ساخت کهنه است و بک‌اند هنگام build در دسترس نبوده. با `pnpm build` دوباره بسازید (یا منتظر تازه‌سازی ۶۰ ثانیه‌ای مرورگر بمانید). |
| `X-Frontend-Build: unknown` | `BUILD_INFO.json` در بسته نیست ⇒ بسته با `pnpm pack:front` ساخته نشده. |

گزارش هر استقرار: `~/kaveh185-deploy-logs/front-deploy-*.log`

## ۷. بازگشت و بازیابی

- **بازگشت نرم:** `bash deploy/front-deploy.sh --rollback` — فقط پیوند `current` را جابه‌جا می‌کند؛ چند میلی‌ثانیه، بی‌ازدست‌دادن داده.
- **بازگشت کامل:** نسخه‌های قبلی در `~/kaveh185-front/releases/` هستند (۳ تای آخر). یکی را دستی فعال کنید:
  ```bash
  ln -sfn ~/kaveh185-front/releases/<id> ~/kaveh185-front/current
  touch ~/Kaveh185-Back/tmp/restart.txt
  ```
- **فرانت را کامل بردارید:** `rm ~/Kaveh185-Back/frontend` — سایت به رفتار قبل برمی‌گردد (۴۰۴ روی صفحه‌ها) و **API سالم می‌ماند**.
