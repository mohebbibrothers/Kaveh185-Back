# راهنمای جامع و فوق‌سریع اتصال فرانت‌اند به بک‌اند کاوه ۱۸۵ (`docs/FRONTEND_HANDOFF.md`)

این سند به‌طور اختصاصی برای **تیم فرانت‌اند (Next.js / React / Vue)** طراحی شده است تا تمام صفحات و جریان‌های کاربری (شرکت‌کننده، لندینگ، آزمون، کارنامه، پنل ادمین و صفحهٔ مراسم قرعه‌کشی حضوری) را در کمترین زمان ممکن و بدون کوچک‌ترین ابهامی به بک‌اند متصل کند.

---

## ۰. جعبه ابزار آماده برای فرانت‌اند کار (Zero-Friction DX Kit)

برای سرعت و راحتی حداکثری شما، فایل‌های زیر در پوشهٔ `docs/` آماده شده‌اند:

1. **فایل TypeScript آمادهٔ کپی (`docs/kaveh185-frontend-sdk.ts`)**:
   - شامل تمامی `interface`های تایپ‌اسکریپت برای ورودی و خروجی تمام اندپوینت‌ها + کلاس آمادهٔ `Kaveh185ApiClient` (مدیریت خودکار هدر `Authorization: Bearer`، کوکی‌ها و `Idempotency-Key`). کافی است این فایل را مستقیماً داخل پروژهٔ Next.js/React خود (`src/lib/kaveh185-frontend-sdk.ts`) کپی کنید!
2. **مجموعهٔ آمادهٔ پست‌من (`docs/kaveh185.postman_collection.json`)**:
   - قابل ایمپورت یک‌کلیکی در **Postman / Insomnia / Bruno** شامل تمام درخواست‌های عمومی، شرکت‌کننده و ادمین با نمونه بدنهٔ فارسی.
3. **مستندات تعاملی زنده روی مرورگر**:
   - **Swagger UI**: `http://localhost:8000/api/v1/docs/`
   - **ReDoc**: `http://localhost:8000/api/v1/redoc/`
   - **کاتالوگ کشف API**: `http://localhost:8000/api/v1/`

## ۱. استاندارد یکپارچهٔ پاسخ‌ها و خطاها (`Response Envelope`)

تمامی پاسخ‌های JSON بک‌اند از یک قالب پاکت یکنواخت پیروی می‌کنند:

### پاسخ موفق (`200 OK` / `201 Created`):
```json
{
  "success": true,
  "status_code": 200,
  "code": "ok",
  "message": "عملیات با موفقیت انجام شد.",
  "trace_id": "019a83f0000070008000000000000001",
  "data": { ... }
}
```

### پاسخ خطا (`400`, `401`, `403`, `404`, `409`, `429`):
```json
{
  "success": false,
  "status_code": 409,
  "code": "exam_already_completed",
  "message": "شما قبلاً در این آزمون شرکت کرده‌اید و هر نفر فقط یک بار مجاز به شرکت در آزمون است.",
  "trace_id": "019a83f0000070008000000000000002",
  "errors": {
    "tracking_code": "KV185-8F9K2M4P"
  }
}
```

## ۲. فلوچارت صفحات شرکت‌کننده (گام‌به‌گام)

### گام ۱: صفحهٔ اول (لندینگ مسابقه + فرم ثبت‌نام + جدول زنده رقابت مساجد)
**روش پیشنهادی (تک‌درخواستی و فوق‌سریع — Single-Request Bootstrap):**
در بدو ورود کاربر به سایت، تنها با **یک درخواست** تمام داده‌های صفحه اول را دریافت کنید:
- **`GET /api/v1/core/bootstrap/`** (یا معادل آن `GET /api/v1/exam/landing/` — بدون نیاز به توکن):
  - `data.exam_status`: وضعیت بازه زمانی آزمون (`window_state`: `"upcoming"` | `"open"` | `"ended"`)، ثانیه‌های مانده تا شروع/پایان (`seconds_until_start`, `seconds_until_end`)، ساعت دقیق سرور (`server_time`, `server_time_jalali`) و لینک کانال‌های ارتباطی حوزه ۱۸۵ شهید کاوه.
  - `data.mosques`: آرایهٔ ۱۷ مسجد فعال (`id`, `code`, `name`, `neighborhood`) آماده برای قرارگیری مستقیم در لیست کشویی (`Select / Dropdown`) فرم ثبت‌نام.
  - `data.leaderboard`: جدول زندهٔ رتبه‌بندی مشارکت ۱۷ مسجد (`leaderboard`) به همراه آمار کل ثبت‌نام‌کنندگان.

*(در صورت تمایل به فراخوانی جداگانه نیز اندپوینت‌های `GET /api/v1/exam/status/`، `GET /api/v1/mosques/` و `GET /api/v1/mosques/leaderboard/` به‌صورت مجزا در دسترس هستند).*

**منطق نمایش دکمهٔ آزمون بر اساس `exam_status.window_state`:**
- `"upcoming"`: هنوز مهلت شروع نشده -> دکمهٔ غیرفعال با متن `status_message` (**«شرکت در آزمون به زودی آغاز می‌شود.»**) + شمارندهٔ معکوس بر اساس `seconds_until_start`.
- `"open"`: آزمون فعال است -> فرم ثبت‌نام و دکمهٔ **«ورود به آزمون»** فعال است.
- `"ended"`: مهلت تمام شده -> دکمهٔ غیرفعال با متن `status_message` (**«مهلت شرکت در آزمون به پایان رسید.»**).

### گام ۲: ثبت فرم مشخصات و انتخاب مسجد (`POST /api/v1/auth/register/`)
هنگام ارسال فرم ثبت‌نام توسط شرکت‌کننده:
```json
{
  "first_name": "محمدحسین",
  "last_name": "کریمی",
  "national_id": "0013542419",
  "phone_number": "09123456789",
  "birth_date": "1382/06/15",
  "mosque_id": 1
}
```
- **پشتیبانی هوشمند از تاریخ تولد شمسی و ارقام فارسی**: فیلد `birth_date` هم تاریخ شمسی (`1382/06/15`، `1382-06-15` یا با ارقام فارسی `۱۳۸۲/۰۶/۱۵`) و هم میلادی (`2003-09-06`) را می‌پذیرد و سن دقیق کاربر (`user.age_years`) را محاسبه می‌کند.
- **ورود مستقیم بدون دردسر (`otp_required: false`)**: در حالت پیش‌فرض، بلافاصله در پاسخ ثبت‌نام توکن‌های JWT در `data.access` (و `data.tokens.access`) برمی‌گردند؛ کافی است هدر `Authorization: Bearer <access>` را ذخیره کنید و دکمهٔ **«ورود به آزمون»** را به کاربر نشان دهید.
- **بازگشت مجدد کاربر قبلی**: اگر کاربری قبلاً ثبت‌نام کرده باشد و دوباره همان کد ملی و موبایل را وارد کند:
  - اگر آزمونش نیمه‌کاره باشد (`exam_eligibility.has_active_attempt == true`)، می‌تواند ادامه دهد.
  - اگر قبلاً آزمون داده باشد (`exam_eligibility.has_completed_exam == true`)، مستقیماً به صفحهٔ کارنامه‌اش (`GET /api/v1/exam/report-card/`) هدایتش کنید.

---

### گام ۳: کلیک روی دکمهٔ «ورود به آزمون» و صفحهٔ ۵ سوال چهارگزینه‌ای
1. **شروع یا ادامهٔ آزمون (`POST /api/v1/exam/start/`)**:
   - به محض کلیک روی دکمهٔ **«ورود به آزمون»**، این اندپوینت را صدا بزنید.
   - سرور به صورت تصادفی رمزنگاری‌شده **۵ سوال چهارگزینه‌ای** از بانک ۳۰ سوالی انتخاب کرده و **ترتیب ۴ گزینهٔ هر سوال** را هم اختصاصاً برای این کاربر بر می‌زند (`shuffled_options`).
   - تایمر بالای صفحه را با `data.remaining_seconds` تنظیم کنید.
   - اگر کاربر وسط آزمون صفحه را Refresh کرد، کافی است `GET /api/v1/exam/current/` (یا دوباره `POST /api/v1/exam/start/`) را صدا بزنید تا دقیقاً همان جلسه با زمان باقی‌مانده و پاسخ‌های قبلی بازیابی شود.
2. **ثبت پاسخ هر سوال به ترتیب ۱ تا ۵ (`POST /api/v1/exam/answer/`)**:
   ```json
   {
     "question_number": 1,
     "selected_position": 3
   }
   ```
   - **قانون عدم امکان رد کردن سوال (`cannot_skip_question`)**: کاربر نمی‌تواند سوال ۱ را بدون جواب رها کند و به سوال ۲ برود. در UI دکمهٔ «ثبت و سوال بعدی» را فقط زمانی فعال کنید که یکی از ۴ گزینه (`1..4`) انتخاب شده باشد.
   - **تضمین ۱۰۰٪ عدم افشای کلید (`Zero Answer Leakage`)**: در پاسخ این اندپوینت هیچ نشانی از درست یا غلط بودن گزینه وجود ندارد.
3. **پایان آزمون و دریافت کارنامه (`POST /api/v1/exam/finish/`)**:
   - پس از ثبت پاسخ سوال ۵ (یا به محض صفر شدن تایمر معکوس)، `POST /api/v1/exam/finish/` را صدا بزنید.
   - اگر هنوز وقت باقی مانده باشد و کاربر به همهٔ ۵ سوال جواب نداده باشد، خطای `400 incomplete_exam_answers` برمی‌گردد تا کاربر را از بستن ناقص آزمون محافظت کند. اگر تایمر به پایان رسیده باشد، آزمون به‌صورت خودکار با پاسخ‌های ثبت‌شده بسته و کارنامه صادر می‌شود.

---

### گام ۴: صفحهٔ کارنامهٔ نهایی (`Report Card`)
خروجی `POST /api/v1/exam/finish/` یا `GET /api/v1/exam/report-card/`:
- شامل خلاصهٔ عملکرد (`total_questions: 5`, `correct_count`, `wrong_count`, `unanswered_count`, `duration_display`, `total_score`)، کد رهگیری قرعه‌کشی (`tracking_code`)، امضای دیجیتال رسید (`receipt_signature`)، پیام تشکر اختصاصی و آرایهٔ کانال‌های ارتباطی حوزه مقاومت بسیج ۱۸۵ شهید کاوه (`communication_channels`) است.
- هم‌زمان یک پیامک تشکر حاوی لینک کانال‌ها و کد رهگیری نیز از طریق صف Outbox برای شرکت‌کننده ارسال می‌شود.

## ۳. راهنمای پنل ادمین و صفحهٔ مراسم قرعه‌کشی حضوری

1. **ورود ادمین**: `POST /api/v1/auth/login/password/` با `identifier` (موبایل یا کد ملی ادمین) و `password`.
2. **مرکز فرماندهی ۳۶۰ درجه ادمین (تک‌درخواستی)**:
   - `GET /api/v1/admin/command-center/` (یا `GET /api/v1/command-center/overview/`)
3. **تنظیمات زمان‌بندی و قوانین آزمون**:
   - `GET` و `PATCH /api/v1/exam/admin/config/` (تغییر تاریخ شروع/پایان، باز/بسته کردن دستی آزمون، تغییر مدت زمان تایمر یا تعداد سوالات).
4. **مدیریت کامل بانک سوال چهارگزینه‌ای و کلید سوالات**:
   - لیست و افزودن سوال: `GET` و `POST /api/v1/exam/admin/questions/`
   - ورود دسته‌جمعی سوالات: `POST /api/v1/exam/admin/questions/bulk/`
   - ویرایش متن سوال، گزینه‌ها یا تغییر گزینهٔ صحیح (همراه با بازتصحیح خودکار کارنامه‌ها): `PATCH /api/v1/exam/admin/questions/{id}/`
5. **کاوشگر چندفیلتره و چندمرتب‌ساز شرکت‌کنندگان (ویژهٔ قرعه‌کشی حضوری)**:
   - `GET /api/v1/reporting/admin/participants/` (یا `GET /api/v1/reporting/lottery/`)
   - پشتیبانی از ترکیب هم‌زمان تمام فیلترها:
     - `mosque_ids=1,3,7` (یک یا چند مسجد هم‌زمان)
     - `exact_correct=5` یا `min_correct=4&max_correct=5`
     - `min_score=80`
     - `max_duration=150` (برحسب ثانیه)
     - `min_age=12&max_age=22` یا `birth_date_from=1380/01/01&birth_date_to=1390/12/29`
     - `search=...` (جستجو روی نام، موبایل، کد ملی یا کد رهگیری)
     - `ordering=-total_score,duration_seconds,-correct_count,age`
6. **موتور اجرای قرعه‌کشی زنده روی استیج مراسم (`POST /api/v1/reporting/admin/lottery/draw/`)**:
   - با ارسال هر ترکیب دلخواه از فیلترهای بالا + `winners_count` (تعداد برندگان اصلی) و `reserves_count` (تعداد برندگان رزرو) و `client_seed` (کد انتخابی مجری مراسم)، سرور برندگان را با تصادفی‌ساز رمزنگاری‌شده (`CSPRNG`) انتخاب کرده و همراه با امضای دیجیتال قابل‌راستی‌آزمایی (`cryptographic_proof.draw_proof_sha256`) برمی‌گرداند.
7. **مشاهدهٔ پرونده و ریز ۵ سوال و گزینه‌های انتخابی هر شرکت‌کننده (توسط ادمین)**:
   - با شناسه کاربر: `GET /api/v1/reporting/admin/participants/{user_id}/`
   - با کد رهگیری قرعه‌کشی: `GET /api/v1/reporting/admin/participants/by-tracking/{tracking_code}/`
8. **دانلود خروجی اکسل ۷ برگی راست‌به‌چپ (`RTL .xlsx`)**:
   - `GET /api/v1/reporting/admin/export.xlsx` (یا `GET /api/v1/reporting/export.xlsx`) — تمام فیلترها و مرتب‌سازی‌های بالا مستقیماً روی خروجی اکسل هم اعمال می‌شوند!

## ۴. جدول کدهای خطای دامنه (`error.code`) برای نمایش پیام در UI

| کد خطا (`code`) | وضعیت HTTP | زمان رخداد و اقدام پیشنهادی در فرانت‌اند |
|---|---|---|
| `exam_not_started_yet` | `403` | کاربر قبل از شروع مهلت آزمون دکمهٔ شروع را زده است -> نمایش شمارندهٔ معکوس تا `starts_at`. |
| `exam_window_ended` | `403` | مهلت شرکت در آزمون تمام شده است -> نمایش پیام پایان مهلت مسابقه. |
| `exam_already_completed` | `409` | کاربر قبلاً در آزمون شرکت کرده است -> هدایت خودکار به صفحهٔ کارنامه (`/api/v1/exam/report-card/`). |
| `exam_time_expired` | `409` | تایمر ۵ دقیقه‌ای کاربر تمام شده و کارنامه‌اش خودکار صادر شده است -> هدایت به صفحهٔ کارنامه. |
| `cannot_skip_question` | `400` | کاربر سعی کرده بدون پاسخ به سوال قبلی به سوال بعدی جواب بدهد -> فوکوس روی اولین سوال بی‌پاسخ. |
| `incomplete_exam_answers` | `400` | کاربر قبل از اتمام تایمر دکمهٔ پایان آزمون را زده اما هنوز همهٔ ۵ سوال را جواب نداده است. |
| `national_id_already_exists` | `409` | کد ملی واردشده قبلاً با شماره موبایل دیگری ثبت شده است. |
| `phone_already_exists` | `409` | شماره موبایل واردشده قبلاً با کد ملی دیگری ثبت شده است. |
