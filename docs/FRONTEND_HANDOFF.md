# راهنمای جامع اتصال فرانت‌اند به بک‌اند کاوه ۱۸۵ (`docs/FRONTEND_HANDOFF.md`)

این سند به‌طور اختصاصی برای **توسعه‌دهندهٔ فرانت‌اند** نوشته شده است تا تمام صفحات و جریان‌های کاربری (شرکت‌کننده و پنل ادمین) را بدون هیچ ابهامی به بک‌اند متصل کند.

---

## ۱. استاندارد کلی پاسخ‌ها و خطاها (`Response Envelope`)

تمامی پاسخ‌های JSON بک‌اند از یک قالب یکنواخت پیروی می‌کنند:

### پاسخ موفق (`200 OK` / `201 Created`):
```json
{
  "success": true,
  "status_code": 200,
  "code": "ok",
  "message": "عملیات با موفقیت انجام شد.",
  "trace_id": "019a83f0000070008000000000000001",
  "data": { ... }
}
```

### پاسخ خطا (`400`, `401`, `403`, `404`, `409`, `429`):
```json
{
  "success": false,
  "status_code": 409,
  "code": "exam_already_completed",
  "message": "شما قبلاً در این آزمون شرکت کرده‌اید و هر نفر فقط یک بار مجاز به شرکت در آزمون است.",
  "trace_id": "019a83f0000070008000000000000002",
  "errors": {
    "tracking_code": "KV185-8F9K2M4P"
  }
}
```

## ۲. فلوچارت صفحات شرکت‌کننده (گام‌به‌گام)

### گام ۱: صفحهٔ اول (لندینگ مسابقه و بررسی وضعیت بازهٔ زمانی آزمون)
در بدو ورود کاربر به سایت، دو اندپوینت زیر را به صورت موازی صدا بزنید:

1. **`GET /api/v1/exam/status/`** (بدون نیاز به توکن):
   - فیلد `data.window_state` یکی از سه مقدار زیر است:
     - `"upcoming"`: هنوز مهلت شروع نشده -> دکمهٔ غیرفعال با متن `data.status_message` (**«شرکت در آزمون به زودی آغاز می‌شود.»**) و شمارندهٔ معکوس بر اساس `data.seconds_until_start` نمایش دهید.
     - `"open"`: آزمون فعال است -> فرم ثبت‌نام / دکمهٔ **«ورود به آزمون»** فعال است.
     - `"ended"`: مهلت تمام شده -> دکمهٔ غیرفعال با متن `data.status_message` (**«مهلت شرکت در آزمون به پایان رسید.»**).
2. **`GET /api/v1/mosques/leaderboard/`** (بدون نیاز به توکن):
   - جدول زندهٔ **رتبه‌بندی مشارکت ۱۷ مسجد** را در صفحهٔ اول نمایش دهید (`data.leaderboard`).

---

### گام ۲: فرم ثبت‌نام شرکت‌کننده و انتخاب مسجد از لیست کشویی
1. برای پر کردن لیست کشویی (`Select / Dropdown`) مساجد در فرم ثبت‌نام، اندپوینت زیر را صدا بزنید:
   - **`GET /api/v1/mosques/`** -> آرایهٔ `data.mosques` شامل `id`, `code`, `name`, `neighborhood`.
2. هنگام ثبت فرم، درخواست زیر را ارسال کنید:
   - **`POST /api/v1/auth/register/`**
   ```json
   {
     "first_name": "محمدحسین",
     "last_name": "کریمی",
     "national_id": "0013542419",
     "phone_number": "09123456789",
     "birth_date": "1382/06/15",
     "mosque_id": 1
   }
   ```
   - **نکتهٔ مهم ۱**: فیلد `birth_date` هم تاریخ شمسی (`1382/06/15` یا با ارقام فارسی `۱۳۸۲/۰۶/۱۵`) و هم تاریخ میلادی (`2003-09-06`) را می‌پذیرد.
   - **نکتهٔ مهم ۲**: در پاسخ، اگر `data.otp_required == false` باشد (حالت پیش‌فرض)، توکن‌های JWT در `data.tokens.access` و `data.tokens.refresh` برمی‌گردند؛ `access` را در هدر `Authorization: Bearer <access>` قرار دهید.
   - اگر همان کاربر قبلاً ثبت‌نام کرده باشد و با همان موبایل و کدملی دوباره فرم را بفرستد، پاسخ `200 OK` با `is_new_user: false` و توکن جدید برمی‌گردد تا بتواند آزمون باز خود را ادامه دهد یا کارنامه‌اش را ببیند.

---

### گام ۳: کلیک روی دکمهٔ «ورود به آزمون» و صفحهٔ سوالات
1. وقتی کاربر روی دکمهٔ **«ورود به آزمون»** کلیک کرد:
   - **`POST /api/v1/exam/start/`** (همراه با هدر `Authorization: Bearer <access>` و ترجیحاً هدر `Idempotency-Key: <uuid>`)
   - پاسخ شامل موارد زیر است:
     - `remaining_seconds`: ثانیه‌های باقی‌مانده از تایمر سرور (تایمر معکوس بالای صفحه را با این عدد همگام کنید).
     - `current_question_number`: شماره سوالی که کاربر الان باید جواب بدهد (`1` تا `5`).
     - `questions`: آرایهٔ ۵ سوال تصادفی که برای این کاربر قرعه افتاده است؛ هر سوال دارای ۴ گزینهٔ برزده‌شده (`position: 1..4`, `text: "..."`) است.
2. **ثبت پاسخ هر سوال (Auto-Save به ترتیب ۱ تا ۵)**:
   - وقتی کاربر گزینهٔ سوال را انتخاب کرد و روی «سوال بعدی» زد:
   - **`POST /api/v1/exam/answer/`**
   ```json
   {
     "question_number": 1,
     "selected_position": 3
   }
   ```
   - **قانون عدم امکان رد کردن سوال**: تا زمانی که به سوال شماره `k` پاسخ داده نشده، ارسال پاسخ برای سوال `k+1` با کد خطای `cannot_skip_question` رد می‌شود. بنابراین دکمهٔ «سوال بعدی» را در فرانت‌اند فقط پس از انتخاب یکی از ۴ گزینه فعال کنید.
3. **پایان آزمون و دریافت کارنامه**:
   - پس از پاسخ به سوال ۵ (یا به محض صفر شدن تایمر معکوس)، اندپوینت زیر را صدا بزنید:
   - **`POST /api/v1/exam/finish/`**
   - پاسخ مستقیماً شیء **کارنامه (`Report Card`)** را برمی‌گرداند!

---

## ۳. راهنمای پنل ادمین و صفحهٔ مراسم قرعه‌کشی حضوری

1. **ورود ادمین با رمز عبور**: `POST /api/v1/auth/login/password/` با `identifier` (شماره موبایل یا کد ملی) و `password`.
2. **نمای یکپارچه داشبورد اصلی ادمین**: `GET /api/v1/admin/command-center/`
3. **تنظیم بازه زمانی و تایمر آزمون**: `GET` و `PATCH /api/v1/exam/admin/config/`
4. **مدیریت بانک سوال چهارگزینه‌ای و کلید سوالات**:
   - فهرست و افزودن سوال: `GET` و `POST /api/v1/exam/admin/questions/`
   - ویرایش سوال یا تغییر گزینهٔ صحیح (همراه با بازتصحیح خودکار کارنامه‌ها): `PATCH /api/v1/exam/admin/questions/{id}/`
5. **کاوشگر چندفیلتره شرکت‌کنندگان ویژهٔ مراسم قرعه‌کشی حضوری**:
   - `GET /api/v1/reporting/admin/participants/`
   - پارامترهای فیلتر قابل ترکیب هم‌زمان:
     - `mosque_ids=1,2,5` (فیلتر یک یا چند مسجد)
     - `exact_correct=5` یا `min_correct=4` (فیلتر تعداد پاسخ درست)
     - `min_age=12&max_age=18` (فیلتر رده سنی نوجوانان/جوانان)
     - `max_duration=120` (کسانی که در کمتر از ۲ دقیقه پاسخ داده‌اند)
     - `ordering=-total_score,duration_seconds` (مرتب‌سازی بر اساس بیشترین امتیاز و کمترین زمان)
6. **دانلود خروجی اکسل ۷ برگی راست‌به‌چپ (`.xlsx`)**:
   - `GET /api/v1/reporting/admin/export.xlsx` (تمام پارامترهای فیلتر بالا روی خروجی اکسل نیز قابل اعمال است!).
