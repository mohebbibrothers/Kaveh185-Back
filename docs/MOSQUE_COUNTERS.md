# شمارنده‌های مسجد — چرا اشتباه می‌شدند و چطور حالا خودترمیم‌اند

> باگِ گزارش‌شده: «وقتی کاربران را دستی از پنل ادمین پاک می‌کنم، چرا هنوز در
> جدولِ مساجد شمرده می‌شوند؟»

## سه علتِ ریشه‌ای (نه یکی)

| # | علت | کجا |
|---|---|---|
| ۱ | شمارنده **فقط بالا می‌رفت**؛ هیچ‌جای کد پایین نمی‌آوردش | `increment_*_count` |
| ۲ | جدول `max(شمارنده، شمارشِ زنده)` می‌گرفت ⇒ عددِ کهنه همیشه برنده بود | `selectors.get_mosque_leaderboard_snapshot` |
| ۳ | حذف در پنل ادمین هیچ سیگنالی به شمارنده نمی‌داد | (سیگنالی وجود نداشت) |

علتِ ۲ بدترین بود: محافظی که برای «دقت» گذاشته شده بود، **ماسکِ باگ** شد.
هر چه شمارنده باد می‌کرد، شمارشِ درست هم پنهان می‌ماند.

## قاعدهٔ جدید

**منبعِ حقیقت، شمارشِ زنده است؛ شمارنده فقط کشِ کارایی است.**

- «ثبت‌نامی» = کاربرانِ `is_active=True` با `role=participant` در آن مسجد.
- «تکمیل‌کننده» = کارنامه‌های `COMPLETED`/`TIMED_OUT` آن مسجد.

## سه لایه‌ای که دیگر نمی‌گذارد عدد از داده جدا بماند

### ۱) سیگنال‌ها — `apps/mosques/signals.py`
هر `save`/`delete` روی `User` و `ExamAttempt` شمارندهٔ مسجدِ مربوطه را از
شمارشِ زنده بازسازی می‌کند. شاملِ:
- حذفِ تکی و **حذفِ گروهی** (حذفِ «انتخاب‌شده‌ها» در پنل ادمین)
- غیرفعال‌کردن، تغییرِ نقش، و **انتقالِ کاربر بین دو مسجد** (هر دو مسجد)
- ذخیره‌هایی که فقط `last_login` را عوض می‌کنند **نادیده گرفته می‌شوند**
  (وگرنه هر ورود یک بازشمارش می‌شد).

### ۲) بازشمارشِ دوره‌ای — `keepalive`
هر ۲ دقیقه، پیش از بررسیِ سلامتِ ربات، شمارنده‌ها ترمیم می‌شوند
(نوشتن فقط وقتی عدد فرق دارد).

### ۳) دستورهای صریح
```bash
python manage.py recount_mosque_stats          # فقط گزارش
python manage.py recount_mosque_stats --fix    # اصلاح
python manage.py heal_site                     # گزارشِ جامع (شمارنده + دادهٔ ساختگی + نیمه‌کاره‌ها)
python manage.py heal_site --fix --purge-simulated
```

## دادهٔ شبیه‌سازی — حالا واقعی است

`simulate_leaderboard` قبلاً فقط شمارنده را بالا می‌برد. چون جدول از دادهٔ
زنده می‌خواند، **هیچ تغییری در جدول دیده نمی‌شد** و بعد از اولین بازشماری
محو می‌شد — که خودش شبیهِ باگ بود. حالا:

- برای هر شرکت‌کننده یک کاربرِ `۰۹۹۰…` + یک کارنامهٔ `SIM-` **واقعی** می‌سازد.
- پاک‌سازی با `--purge` یا `heal_site --purge-simulated` (فقط همان پیشوندها؛
  هیچ کاربرِ واقعی لمس نمی‌شود).

## اگر باز هم عددی عجیب دیدید

```bash
python manage.py heal_site --fix
```

خروجی، مسجدِ منحرف و هر دو عدد (ذخیره‌شده ⇒ واقعی) را نشان می‌دهد. اگر
اختلاف برگشت، یعنی کدی بیرون از سیگنال‌ها مستقیم `UPDATE` می‌زند — همان
خط را پیدا کنید، نه اینکه عدد را دستی درست کنید.
